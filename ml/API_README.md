# Контракт ML API для backend

Этот документ описывает фактические запросы и ответы текущего ML-сервиса. В сервисе две модели: **city — 25 признаков**, **region — 26 признаков**. Модели возвращают вероятность составного исхода, определённого при обучении.

Базовый адрес: `http://<ml-host>:8000`. В примерах — `http://localhost:8000`; в Docker используйте адрес ML-сервиса, доступный из backend. Префикса `/api` у ML нет. Все примеры путей ниже добавляются к базовому адресу.

Сервис сам не проверяет JWT и роли. Доступ пользователей и право на переобучение контролирует backend; специальный Authorization-заголовок ML сейчас не требует.

Версии структур: **predict — 5**, **CSV для retrain — 6**, профессии — `notebook-13-v1`. Это версии форматов, а не значения поля `model_version`: оно обозначает конкретный обученный комплект и меняется после успешного переобучения.

## 1. Все эндпоинты

| Метод | Путь | Что отправляем | Что получаем |
|---|---|---|---|
| POST | `/predict` | JSON одного обследования или сводной записи | Один прогноз выбранной модели и model_version |
| POST | `/predictions/predict` | Тот же JSON | Полный синоним `/predict` |
| POST | `/retrain` | multipart/form-data, файл в поле dataset | Результат обучения двух моделей, их метрики и новую версию |
| GET | `/metrics` | Без тела | JSON-массив метрик двух активных моделей |
| GET | `/dataset/schema` | Без тела | Схему CSV, кодировки профессий и JSON Schema для predict |
| GET | `/health` | Без тела | Состояние моделей и активную версию |
| GET | `/docs` | Без тела | Swagger UI |
| GET | `/redoc` | Без тела | ReDoc |
| GET | `/openapi.json` | Без тела | Машиночитаемое описание API |

Swagger также регистрирует служебный GET `/docs/oauth2-redirect`; backend-клиенту он не нужен. Документационные GET поддерживают HEAD.

## 2. POST /predict — прогноз

`Content-Type: application/json`. Тело — один объект, не массив. Ответ `200 application/json`.

`model_kind` выбирается явно: ML не определяет модель автоматически по району. Сейчас обе модели допускают все шесть кодов `region`. Название city означает набор признаков и обследование за выбранный период, а region — сводные клинические и экологические показатели.

| Модель | Какой вход ожидается | Что означает положительный класс |
|---|---|---|
| city | Показатели одного обследования и метка экологического периода | Хотя бы один из: инсульт, СН, ИМ/стенокардия/ИБС, АГ или смерть в соответствующей записи обследования |
| region | Сводные показатели пациента за период наблюдения | Хотя бы один учитываемый сердечно-сосудистый исход, госпитализация или смерть за период; состав отличается от city, АГ отдельно в цель не входит |

В обучающих записях city клинические измерения 2013 используются для 2013/2017, поздние — для 2019/2021; возраст увеличивается от исходного на 0/4/6/8 лет. Глюкоза берётся из позднего столбца, как в исходном блокноте. Для region обучение использует исходный возраст 2013 года, средние рост/вес/липиды двух обследований, исходный статус хронических заболеваний лёгких и позднюю глюкозу. Среднее для region — (значение 2013 + значение 2019–2021) / 2; если один из липидных показателей неизвестен, среднее тоже неизвестно. Backend передаёт уже выбранные сводные значения; predict сам не читает историю пациента и не усредняет её. Для нового пациента ID и присутствие в обучающей базе не нужны.

### Обязательные поля JSON

| Поле | Тип | Допустимые значения / смысл |
|---|---|---|
| model_kind | string | `city` или `region` |
| gender | integer | 1 — мужчина, 2 — женщина |
| age | number | Возраст, 0–120 включительно; дробное число допускается |
| height | number | Рост, см: строго больше 0, не больше 250 |
| weight | number | Вес, кг: строго больше 0, не больше 300 |
| alcohol | integer | 0 — нет, 1 — употреблял ранее, 2 — употребляет сейчас |
| profession | integer | 1–13 по таблице ниже |
| region | integer | 1–6 по таблице ниже |
| chronic_lung_disease | integer | Хронические заболевания лёгких: 0 — нет, 1 — есть |
| year | integer / null | Для city обязателен: 2013, 2017, 2019 или 2021. Для region — null либо поле отсутствует |

Обязательное поле нельзя заменять null. Значение year у city — **метка экологического периода**, а не год регистрации пациента и не текущий календарный год:

| year | Период исходных экологических данных |
|---:|---|
| 2013 | 2009–2013 |
| 2017 | 2014–2017 |
| 2019 | 2018–2019 |
| 2021 | 2020–2021; фактически главным образом 2020 |

Значения 2025/2026 автоматически не заменяются на 2021: такой запрос вернёт 422. Для region любое значение year, кроме null, также вернёт 422.

### Необязательные лабораторные показатели

| Поле | Тип | Смысл |
|---|---|---|
| glucose | number / null | Глюкоза |
| cholesterol | number / null | Общий холестерин |
| hdl_cholesterol | number / null | Холестерин ЛПВП |
| ldl_cholesterol | number / null | Холестерин ЛПНП |
| triglycerides | number / null | Триглицериды |

Числа должны быть конечными и неотрицательными. Неизвестное значение передавайте как null или не передавайте поле. **Ноль — реальное числовое значение, он не означает «нет данных».** NaN и Infinity не допускаются. ML не конвертирует единицы: используйте единицы обучающего датасета, для глюкозы/липидов — ммоль/л.

Поле cholesterol остаётся в общем контракте, хотя выбранная city-модель не использует общий холестерин как отдельный признак. У region общий холестерин используется. ИМТ сервис вычисляет сам из роста и веса.

### Необязательная история диагнозов

Эти поля принимаются для совместимости, но **не участвуют в признаках текущих двух моделей**. Их можно полностью опустить. Отправлять диагнозы для получения прогноза не требуется.

| Флаг 0/1/null | Год диагноза integer/null | Диагноз |
|---|---|---|
| stroke | stroke_year | Инсульт |
| heart_failure | heart_failure_year | Сердечная недостаточность |
| cad_chd_ihd | cad_chd_ihd_year | Нарушение ритма / другие ИБС |
| angine | angine_year | Стенокардия; имя поля именно angine |
| myocardial_infarction | myocardial_infarction_year | Инфаркт миокарда |
| arterial_hypertension | arterial_hypertension_year | АГ |

Допустимый год — 1900–2100 включительно. Неизвестный год — null, не условный 1950. Эти поля не являются обучающим target.

### Пример region

Здесь приведены иллюстративные сводные показатели; значения своего пациента выбирает backend:

```json
{
  "model_kind": "region",
  "year": null,
  "gender": 1,
  "age": 55,
  "height": 175,
  "weight": 80,
  "alcohol": 0,
  "profession": 2,
  "region": 5,
  "chronic_lung_disease": 0,
  "glucose": 5.7,
  "cholesterol": 5.2,
  "hdl_cholesterol": 1.5,
  "ldl_cholesterol": 3.4,
  "triglycerides": 1.2
}
```
Ответ:

```json
{
  "predictions": [
    {
      "disease": "region",
      "probability": 0.7536292308836605,
      "prediction": 1
    }
  ],
  "model_version": "20261105T174530Z-7af035de0d7c"
}
```

### Как разбирать ответ

| Поле | Тип | Значение |
|---|---|---|
| predictions | array | При одном запросе содержит ровно один результат выбранной модели |
| predictions[].disease | string | Код `city` или `region`, не название отдельного заболевания |
| predictions[].probability | number | Вероятность положительного составного исхода, от 0 до 1 |
| predictions[].prediction | integer | 1 при probability >= 0.5, иначе 0 |
| model_version | string | Непрозрачный идентификатор использованного комплекта моделей |

Например, probability=0.72 соответствует 72%. Не умножайте значение дважды и не считайте его уже процентом. Для отображения можно округлить, но в DTO и хранилище сохраняйте исходный Double. Это не семь вероятностей отдельных заболеваний.

Если нужны оба результата, сделайте два запроса с соответствующими входами city и region. Единого эндпоинта, автоматически возвращающего обе модели по одному набору данных, сейчас нет. Версию каждого результата сохраняйте из его ответа.

### Поля, которые больше не передаются

`hip_measurement`, `non_hdl_cholesterol`, `vldl_cholesterol`, `apolipoprotein_a`, `apolipoprotein_b`, `cholesterol_status` удалены. В predict также не передаются id, target, готовый ИМТ или экологические показатели.

**Лишние ключи JSON запрещены даже со значением null** и возвращают 422. Их нужно убрать из сериализуемого DTO, а не просто перестать заполнять.

## 3. POST /retrain — переобучить обе модели

Запрос — `multipart/form-data`, имя файлового поля **dataset**. Часть файла: `Content-Type: text/csv; charset=utf-8`, filename, например patients.csv. Boundary формирует HTTP-клиент. Нельзя отправлять CSV как JSON-строку, путь к файлу или сырое тело text/csv вместо multipart.

```bash
curl -X POST http://localhost:8000/retrain \
  -F 'dataset=@app/data/train_dataset.csv;type=text/csv'
```

### Какой CSV нужен

Локальный закрытый датасет (не входит в Git): `app/data/train_dataset.csv`, 2987 строк и 69 столбцов. **Одна строка — один пациент со всей доступной историей.** Нет готовых срезов по годам и нет отдельных столбцов model_kind, year, target. Сами значения обследований и исходов по годам остаются в разных столбцах одной строки.

Сервис сам создаёт записи city за 2013/2017/2019/2021, сводные записи region, целевые метки, экологические признаки и ИМТ. Поэтому одного набора текущих анализов без наблюдаемых исходов за нужные периоды для переобучения недостаточно. Backend не должен заполнять отсутствующую историю нулями или предсказаниями модели.

Правила файла:

- UTF-8; BOM допускается. Разделитель — запятая, десятичная точка. Значения с запятыми нужно заключать в кавычки по правилам CSV.
- Заголовки должны совпадать со схемой, не повторяться; все 69 столбцов обязательны. Порядок во входном файле несущественен, для выгрузки используйте csv_columns из схемы.
- id — непустой уникальный идентификатор пациента. Он нужен для группировки выборки, а не для поиска экологии.
- Бинарные столбцы — известные 0/1; пустое значение здесь отклоняется. Это относится и к хроническим заболеваниям лёгких.
- Для лабораторных показателей пустая ячейка означает неизвестное значение. Возраст, рост и вес обоих обследований обязательны.
- Пол: муж/жен или 1/2; алкоголь: нет/употреблял ранее/да в настоящее время либо 0/1/2.
- Профессия: название одной из 13 категорий, исходный вариант из словаря либо новый код 1–13.
- Район — строка: рудничный, центральный, заводский, кировский, ленинский или сельская местность. Код город/село — 1/2; для села используется сельская местность.
- Дополнительные исходные столбцы игнорируются. Но готовые model_kind, year или target во входе отклоняются, чтобы не смешивать исходную таблицу с подготовленными записями.

Пять удалённых показателей и итоговый код холестерина не требуются. Они отсутствуют в образце. Даже если итоговый код есть в исходной выгрузке, модель его не использует.

Максимум по умолчанию — **50 MiB (52 428 800 байт) содержимого файла**; меняется через ML_MAX_UPLOAD_BYTES.

### Поведение и ответ

Это **синхронный долгий запрос**: 200 возвращается после завершения обучения и активации двух моделей. Не возвращаются 202, job_id или адрес опроса состояния задачи. Для retrain нужен отдельный длительный timeout; в текущем Kotlin MlClient уже предусмотрено 15 минут, для обычных вызовов — 10 секунд.

Во время обучения predict продолжает обслуживать предыдущий комплект. После успешного обучения city и region активируются вместе, версия меняется. При ошибке прежний комплект остаётся активным. Параллельная попытка переобучения возвращает 409.

После timeout проверьте /health и /metrics: обучение могло завершиться, даже если клиент не дождался ответа. Не считайте разрыв соединения подтверждением отката или отмены обучения. Эндпоинта отмены сейчас нет.

## 7. Ошибки и их разбор

| HTTP | Когда | Что делать backend |
|---:|---|---|
| 200 | Успешный запрос | Разобрать ответ соответствующего эндпоинта |
| 409 | Уже выполняется retrain | Сообщить о занятом обучении, не запускать параллельные повторы |
| 413 | Файл превышает лимит | Проверить размер CSV |
| 422 | Некорректный JSON, поля, коды, период или CSV | Показать/сохранить detail; исправить данные |
| 503 | Активные модели недоступны или несовместимы | Проверить health, состояние ML и наличие обученного комплекта |
| 500 | Необработанная внутренняя ошибка | Зафиксировать HTTP-код и тело, сообщить об ошибке ML; успешного retrain не было подтверждено |
| 404 / 405 | Неизвестный путь / неверный метод | Исправить вызов клиента |

У 422 есть **две формы**.

Проверка JSON / отсутствие multipart-поля dataset — detail является массивом:

```json
{
  "detail": [
    {
      "loc": [
        "body",
        "chronic_lung_disease"
      ],
      "msg": "Field required",
      "type": "missing"
    }
  ]
}
```
Ошибка проверки данных CSV или бизнес-валидация — detail является строкой, например:

```json
{
  "detail": "Нужна одна строка на пациента без model_kind, year и target; сервис вычислит их сам"
}
```
Для 409/413/503 также используется строковый detail. Пример 409:

```json
{
  "detail": "Переобучение уже выполняется"
}
```

В error DTO принимайте detail как string **или** массив объектов, либо как JSON-узел с последующим разбором. Внутренний 500 может иметь обычное текстовое тело, поэтому нельзя безусловно требовать JSON для любого неуспешного ответа.

## 8. Что изменить в текущем Kotlin backend

1. В MlPredictRequest добавить model_kind, year и обязательный chronic_lung_disease. Выбирать city/region явно, не отправлять дату регистрации как year.
2. Удалить из сериализуемого DTO hip_measurement, non_hdl_cholesterol, vldl_cholesterol, apolipoprotein_a, apolipoprotein_b. Не добавлять cholesterol_status. Старые ключи с null тоже дадут 422.
3. Привести profession к новой классификации 1–13. Проверить алкоголь: ML ждёт 0/1/2; текущий перевод из БД 1/2/3 через minus(1) подходит, если БД использует именно эту кодировку.
4. Не подставлять 0.0 в неизвестные обязательные рост/вес и 1950 в неизвестный год диагноза. Обязательные измерения должны быть известны; неизвестные необязательные поля — null/отсутствуют.
5. В MlDiseasePrediction добавить prediction, если он нужен приложению. В MlPredictResponse сохранить model_version. Не ожидать семь элементов в predictions: при одном запросе приходит один.
6. Заменить справочник названий моделей: коды теперь city и region. Старые general/ah/stroke/mi/... больше не возвращаются. Рекомендуемые подписи — «Составной исход обследования» и «Сводный исход за период наблюдения».
7. Переделать экспорт для retrain: одна широкая строка на пациента, 69 полей по /dataset/schema. Убрать генерацию готовых year/model_kind/target. Наблюдаемые годовые диагнозы и смерти должны реально присутствовать в источнике; из одной текущей анкеты их получить нельзя.
8. В MlRetrainResponse добавить model_version, metrics, input_patients, prepared_rows. Поля models_dir/metrics_json/metrics_csv сервис не возвращает; сохранение выполняется внутри ML.
9. В MlMetric предусмотреть validation_* и *_patients, iterations, threshold и необязательный model_variant либо разрешить игнорирование новых полей. /metrics разбирается как список, не объект с metrics.
10. Не фиксировать версию модели строкой 1.0.0. Использовать значение из ответов ML. Обрабатывать обе формы detail, 409/413/422/503 и отдельный длительный timeout для retrain.
